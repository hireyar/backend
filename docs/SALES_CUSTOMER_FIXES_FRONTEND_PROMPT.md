# پرامپت اصلاحات فرانت فروش — 2026-10-21

در ریپوی فرانت Angular، اصلاحات زیر را روی پنل فروش موجود و مدیریت فروش سوپرادمین اعمال کن. مرجع API، SALES_PANEL_API.md است. طراحی و ورود فعلی را حفظ کن؛ این درخواست بازسازی پنل نیست.

۱. در فهرست مشتریان پنل فروش و مدیریت فروش سوپرادمین، ورودی «جستجوی نام یا شماره موبایل مشتری» اضافه کن. جستجو سروری است:

```http
GET /api/sales/leads?search=...&page=1&pageSize=20&status=Registered
GET /api/admin/sales/leads?search=...&page=1&pageSize=20&status=Registered&agentId=...
```

search اختیاری و حداکثر۲۰۰کاراکتر است؛ بخشی از نام یا شماره موبایل را تطبیق می‌دهد. status و agentId اختیاری‌اند؛ agentId فقط فیلتر مدیریتی است. هنگام تغییر/پاک‌کردن جستجو صفحه را۱ کن و فیلترهای دیگر را حفظ کن. query را encode کن، debounce داشته باش و پاسخ قدیمی درخواست قبلی را نادیده بگیر. جدول و total را از پاسخ سرور بگیر؛ جستجوی محلی روی صفحه فعلی نکن. ساختار Page پاسخ `{items,total,pageNumber,pageSize}` است. توکن مستقل Sales برای مسیر اول و SystemAdmin برای مسیر دوم استفاده شود.

۲. فرم ثبت مشتری همچنان `POST /api/sales/leads` با `{mobile,customerName,note}` است؛ mobile قالب ASCII `09xxxxxxxxx`، نام اجباری حداکثر۲۰۰ و note اختیاری حداکثر۲۰۰۰کاراکتر. پس از موفقیت، جدول و dashboard را دوباره بخوان و وضعیت پاسخ سرور را نمایش بده:

- Waiting: «ثبت‌نام نکرده»؛ برای شماره جدید.
- Registered: «ثبت‌نام کرده»؛ برای حساب موجود بدون خرید تأییدشده، شامل هدیه/تریال فعال.
- Won: «خرید موفق»؛ سابقه خرید تأییدشده، حتی اگر اشتراک فعلی منقضی باشد.
- Dead: وضعیت موجود بی‌سرانجام؛ رفتار پیگیری قبلی حفظ شود.

۳. خطاها ProblemDetails هستند؛ code و title را بخوان. دو خطای زیر HTTP409 دارند و متن فارسی دقیق نمایش داده شود:

| code | متن |
|---|---|
| lead_already_claimed با title فارسی سرور | این شماره توسط کارشناس فروش دیگری ثبت شده است |
| customer_has_active_subscription | این شماره قبلا ثبت شده و اشتراک فعال دارد |

اگر هر دو شرط برقرار باشند، بک‌اند خطای تعلق به فروشنده دیگر را مقدم می‌کند. برای سایر حالت‌های lead_already_claimed (از جمله تکرار همان فروشنده) fallback عمومی «این شماره قبلاً ثبت شده است» را حفظ کن. نام یا اطلاعات فروشنده دیگر نمایش داده نمی‌شود. خطا را موفقیت ثبت تلقی نکن و ردیف محلی اضافه نکن.

۴. مشتری بدون انتساب دارای هدیه یا تریال فعال **قابل افزودن است**؛ اشتراک منقضی نیز مانع نیست. فقط اشتراک پولی مؤثر و فعال مانع افزودن است. مجازبودن را در فرانت از روی وجود هر اشتراک یا سابقه خرید حدس نزن و precheck مسدودکننده نساز؛ تصمیم از پاسخ POST گرفته شود. ثبت مشتری در این فرم حساب/هدیه/اشتراک جدید نمی‌سازد. وضعیت Won به معنی فعال‌بودن اشتراک امروز نیست.

۵. در «پورسانت من»، اطلاعات از `GET /api/sales/commissions` خوانده شود. تأیید خرید اول و هر تمدید، ردیف مستقل با Kind=FirstSale/Renewal و نرخ/مبلغ واقعی سرور می‌سازد؛ هیچ درصد ثابتی در UI نگذار. ثبت مشتری به‌تنهایی پورسانت تاریخی نمی‌دهد؛ هدیه/تریال و خرید بسته مصاحبه پورسانت ندارند. مبلغ HTTP ریال است؛ نمایش تومان با تقسیم بر۱۰ و برچسب روشن. Holding هفت‌روزه و چرخه درخواست واریز فعلی را حفظ کن. پس از refresh یا بازگشت به صفحه، جدول/مجموع‌ها را از API تازه کن.

۶. حذف کامل مشتری در این درخواست لغو شده است؛ دکمه یا فراخوانی DELETE جدید اضافه نکن. loading/empty/error و RTL فعلی را رعایت کن. تست رابط شامل جستجوی نام/موبایل، حفظ فیلتر و pagination، دو پیام خطا و اولویت، افزودن هدیه/تریال/منقضی، وضعیت‌های پاسخ، و نمایش مستقل پورسانت خرید و تمدید با درصدهای متفاوت سرور باشد.
