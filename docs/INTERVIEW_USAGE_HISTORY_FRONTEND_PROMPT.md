# پرامپت Angular: صفحه سوابق مصرف مصاحبه

در پنل Angular هایریار صفحه جدید «سوابق مصرف» را مطابق الگوهای فعلی UI، RTL، جدول، routing و دسترسی‌ها پیاده کن. بک‌اند این قرارداد را آماده دارد؛ [قرارداد کامل](INTERVIEW_USAGE_HISTORY_API.md) مرجع است. API یا محاسبه مالی جدید اختراع نکن.

۱. لینک «سوابق مصرف» را کنار اشتراک/بسته‌ها فقط برای Owner اضافه کن؛ route guard هم Owner باشد. Recruiter به این API دسترسی ندارد. صفحه حتی با پایان اشتراک قابل خواندن باشد و کاربر را به خرید اجباری هدایت نکند.

۲. از GET /api/subscriptions/usage استفاده کن؛ queryهای page (شروع1)، pageSize (پیش‌فرض20، سقف100)، status اختیاری، fromUtc و toUtc اختیاری را سروری بفرست. پاسخ items/total/pageNumber/pageSize است. تغییر فیلتر صفحه را1 کند؛ درخواست قدیمی با تغییر فیلتر لغو شود. loading، empty و error با retry دستی داشته باشد. total تعداد رکوردهای فیلترشده است، مجموع اعتبار مصرف‌شده نیست.

۳. جدول شامل نام کارجو candidateName، موقعیت positionTitle، قالب templateTitle، نوع interviewType، وضعیت status، تاریخ ایجاد createdAtUtc، مهلت دعوت expiresAtUtc، مدت تنظیم‌شده configuredDurationSeconds، شروع startedAtUtc، پایان endedAtUtc، مدت واقعی actualDurationSeconds، اعتبار کسرشده creditsConsumed و دکمه جزئیات باشد. برای جدول باریک اطلاعات زمان را در بخش بازشونده/جزئیات مرتب کن تا افقی و ناخوانا نشود. برای null علامت «—» بگذار. زمان‌های سرور UTC هستند؛ نمایش محلی/شمسی مطابق helper موجود پروژه و نام منطقه زمانی روشن باشد. ثانیه‌ها را به دقیقه:ثانیه تبدیل کن.

۴. این مدل اعتبار تعدادی دارد. مصرف را به‌شکل «۱ مصاحبه»/«۰ مصاحبه» نمایش بده؛ قیمت ریالی، دلار، نرخ، هزینه دقیقه‌ای یا حاصل‌ضرب زمان اضافه نکن. ایجاد دعوت سهمیه را رزرو می‌کند و هنوز مصرف نیست؛ isReserved=true برچسب «۱ سهمیه رزروشده» داشته باشد. creditsConsumed تنها منبع کسر قطعی است. لغو/انقضای پیش از شروع صفر است و لغو پس از شروع می‌تواند مصرف۱ داشته باشد. actualDurationSeconds صرفاً زمان سپری‌شده است و مبنای کسر نیست.

۵. نگاشت وضعیت‌ها:
- Created: ایجادشده
- InProgress: در حال انجام
- Completed: پایان‌یافته
- Cancelled: لغوشده
- Expired: منقضی‌شده
- Replaced: جایگزین‌شده
- Revoked: دسترسی باطل‌شده
- Deleted: حذف‌شده

گزینه «همه وضعیت‌ها» query status را حذف کند. ردیف‌های لغوشده، منقضی و حذف‌شده را خودکار پنهان نکن. فیلتر بازه بر زمان ایجاد است؛ مرز پایین شامل و بالا غیرشامل. روزهای شمسی انتخاب‌شده را با ابزار موجود به مرز روزهای محلی و سپس UTC/Z تبدیل کن؛ پایان روز انتخابی را ابتدای روز بعد بفرست. fromUtc بعد از toUtc را قبل از درخواست رد کن.

۶. برای جزئیات GET /api/subscriptions/usage/{interviewId} را بخوان. پاسخ interview (همان فیلدهای ردیف) و events دارد. drawer/صفحه جزئیات اطلاعات زمانی و اعتبار را نشان دهد و timeline رویدادها را به ترتیب برگشتی رندر کند. event دارای id/eventType/occurredAtUtc/creditsConsumed/isHistorical است. از id به‌عنوان track key استفاده کن.

۷. نگاشت timeline: Created «ایجاد دعوت»، Reserved «رزرو سهمیه»، Started «شروع مصاحبه»، CreditConsumed «کسر اعتبار»، Completed «پایان مصاحبه»، Cancelled «لغو»، Expired «انقضا»، Replaced «جایگزینی دعوت»، AccessRevoked «ابطال دسترسی»، Deleted «حذف از فهرست مصاحبه‌ها»، Released «آزادسازی رزرو». در رویداد CreditConsumed یک واحد کسر نمایش بده؛ Started مصرف جداگانه ندارد. مصرف کل جزئیات از interview.creditsConsumed است. isHistorical=true برچسب «بازسازی‌شده از اطلاعات قبلی» داشته باشد؛ درباره کامل‌بودن timeline قدیمی وعده نده.

۸. اگر replacementInterviewId موجود بود، لینک به جزئیات مصرف دعوت جایگزین بده. برای مصاحبه Deleted جزئیات مصرف همچنان کار می‌کند؛ دکمه ورود به صفحه عملیاتی/گزارش را بدون پشتیبانی مسیر موجود نمایش نده. نامعتبر/سازمان دیگر404 است. توکن، کد دعوت، لینک حساس یا داده دسترسی کارجو در این API وجود ندارد و برای این صفحه از endpoint access استفاده نکن.

۹. endedAtUtc/startedAtUtc/actualDurationSeconds ناموجود را از expiresAtUtc حدس نزن. configuredDurationSeconds مدت مجاز تنظیم‌شده است؛ زمان قرار ملاقات مجزایی در قرارداد نیست. Expired در لیست می‌تواند پیش از ثبت رویداد timeline دیده شود: worker هر۳۰ثانیه و هر نوبت حداکثر۲۰۰مورد را ثبت می‌کند. دکمه تازه‌سازی دستی کافی است؛ polling تند یا retry بی‌پایان اضافه نکن.

۱۰. 401 مطابق جریان ورود موجود، 403 صفحه عدم دسترسی، 404 جزئیات پیدا نشد، 400 خطای فیلتر و 5xx پیام قابل‌فهم با retry دستی باشد. داده حساس را در console/localStorage ذخیره نکن. پارامتر سازمان/نقش از کلاینت نفرست. چک فرانت جای احراز هویت/کنترل دسترسی سرور نیست.

۱۱. تست‌های معنادار UI/service را طبق زیرساخت موجود اضافه و اجرا کن: ایجاد با مصرف۰ و رزرو۱، شروع با مصرف۱، لغو پیش/پس از شروع، انقضا با زمان‌های null، فیلتر و page reset، جزئیات حذف‌شده و جایگزین، برچسب تاریخی، مرز تاریخ و403. build را اجرا و نتیجه و فایل‌های تغییرکرده را گزارش کن.
