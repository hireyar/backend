# پرامپت پیاده‌سازی فرانت پنل فروش

به‌روزرسانی قطعی ADR-078: ورود فروش در `/salesadmin/{randomkey}` است، **بدون کپچا**. guard مقدار randomkey را از segment می‌خواند و در X-Sales-Entry به GET /api/sales/auth/entry می‌دهد.404 به معنی مسیر/کلید نامعتبر یا پنل غیرفعال است؛ فرم پس از entry موفق نمایش داده شود. همین header روی login/me/logout لازم است؛ بقیه Sales API با token مستقل هستند. تغییر کلید، token قبلی را401 می‌کند. key واقعی را در bundle/env عمومی/لاگ/analytics hardcode یا منتشر نکن؛ SalesAdmin تنظیم بک‌اند خصوصی است. مسیر قدیمی /sales/login حذف شود و ورود با mobile/password بماند؛ endpoint، تصویر یا ورودی کپچا نساز.

در ریپوی Angular، دو نمای فایل sales_panel (2).html را با design system فعلی پیاده کن. نمونه یک طرح نمایشی است؛ alert، آرایه شماره‌های ثابت، تاریخ/شمارش/مبلغ ساختگی و innerHTML داده کاربر را وارد محصول نکن. قرارداد قطعی [SALES_PANEL_API](SALES_PANEL_API.md) است؛ درخواست صریح کاربر برای فرم پورسانت بر نمونه مقدم است. فقط خرید و تمدید اشتراک پورسانت دارند.

۱. مسیر مستقل `/salesadmin/{randomkey}` با موبایل/رمز مثل فرم سوپرادمین، بدون کپچا. حساب فقط از سوپرادمین ساخته می‌شود. از /api/sales/auth/login و توکن مستقل کوتاه‌مدت Sales استفاده کن؛ token namespace و interceptor/guard جدا باشد. سوپرادمین و پنل سازمان نباید توکن فروش را مصرف کنند. رمز فقط هنگام ساخت/reset ادمین یک بار در modal نشان داده و بعد از بستن پاک شود. JWT در حافظه؛ با401 ورود مجدد. خطای400/401/409/429 با code و پیام مناسب؛ لاگ رمز/توکن/بدنه حساس نداشته باش.

۲. صفحه فروشنده: آمار dashboard، فرم تماس mobile/customerName/note، تب‌های مشتریان من/منتظر ثبت‌نام/ثبت‌نام‌شده/خرید موفق/بی‌سرانجام، جدول با صفحه‌بندی سرور، وضعیت، تاریخ تماس/ثبت‌نام، یادداشت و عملیات پیگیری. وضعیت و تعداد از API، نه تشخیص روی یک صفحه. follow-up فرم note و تاریخ اختیاری دارد و تماس دوباره، لید Dead را Waiting می‌کند. این فقط یادآوری ثبت‌شده در فهرست است؛ پیام «پیامک ارسال شد» نشان نده.409 ثبت شماره پیام عمومی قبلاً ثبت شده است و نام فروشنده دیگر را افشا نکن. جابه‌جایی بین دو نقش نمونه HTML در محصول راه احراز هویت نیست.

۳. بخش «پورسانت من» را با یک فرم جدید بساز: تاریخ ثبت‌نام مشتری از/تا، وضعیت و دکمه اعمال/پاک‌کردن. تاریخ شمسی تهران را به UTC همان روز تبدیل کن؛ to ابتدای روز بعد و exclusive است. این فیلتر تاریخ فروش/تمدید نیست. همه تاریخ‌های قابل نمایش از timestamp واقعی و با fa-IR/Persian calendar نمایش داده شوند. جدول مشتری/ثبت‌نام/نوع خرید اول یا تمدید/مبلغ فاکتور/تاریخ فروش/درصد/پورسانت/وضعیت/انتخاب. ردیف هر سفارش مستقل است و یک مشتری می‌تواند چند ردیف داشته باشد. summary کل پورسانت، قابل درخواست، درانتظار و پرداخت‌شده از مجموع API است، نه جمع ردیف‌های صفحه فعلی. DB/HTTP ریال؛ نمایش تومان با تقسیم۱۰ و برچسب صریح.

۴. checkbox فقط برای canRequest=true؛ دکمه «درخواست واریز» جمع انتخاب‌های مشخص را نشان دهد. انتخاب‌ها به شناسه ردیف وابسته باشند و با تغییر فیلتر پاک شوند. POST /api/sales/payouts شامل requestId غیرخالی و commissionIds یکتا، حداکثر۱۰۰. requestId در retry شبکه ثابت؛ هنگام submit دکمه غیرفعال و ردیف‌ها busy. پس از موفقیت جدول/جمع‌ها/سوابق درخواست‌ها را refetch کن؛ وضعیت Requested و انتخاب مسدود. Holding تا پایان۷روز غیرفعال، Paid و Returned نیز دوباره انتخاب نمی‌شوند. تمدید بعدی ردیف جدیدی می‌آورد و پس از۷روز مستقل قابل درخواست است. برگشت ادمین همان دوره را آزاد نمی‌کند. با409 جدول را تازه و دلیل ناسازگاری را نشان بده؛ افزایش مبلغ/تعداد محلی نکن. فرم سابقه درخواست‌ها مبلغ/تاریخ/وضعیت/توضیح بررسی دارد؛ جزئیات ردیف‌های آن را از commissions?payoutId و سابقه هر مشتری را از commissions?leadId بگیر.

۵. در سوپرادمین فعلی بخش فروش اضافه کن: آمار کل، فهرست صفحه‌بندی نیروها، ایجاد/ویرایش نام/موبایل/درصدهای مستقل/فعال، reset رمز، انتقال لید با انتخاب مقصد فعال/includeCustomers و دلیل اجباری. تذکر روشن کنار انتقال: پورسانت‌های قبلی برای فروشنده قبلی می‌مانند و فقط انتساب و فروش‌های آینده منتقل می‌شوند. نیروی غیرفعال ورود ندارد؛ سابقه و درخواست‌های او برای ادمین محفوظ‌اند. فرم درخواست واریز شامل فروشنده، مبلغ ریالی/تومانی، تاریخ، وضعیت و اقدام ثبت واریز با توضیح رسید یا برگشت با دلیل است؛ تأیید به معنی ثبت واریزی است که ادمین انجام داده، API پول منتقل نمی‌کند. audit را فقط ادمین ببیند. فهرست لید/پورسانت با فیلتر agentId و تاریخ از مسیرهای مدیریتی خوانده شود.

۶. loading/empty/error، responsive و RTL، کنترل keyboard/focus، escape خروجی متن و validation نام/شماره/دو رقم درصد/بازه تاریخ را رعایت کن. فهرست‌ها pagination واقعی دارند. پارامتر agentId از فروشنده برای scope استفاده نشود. ثبت‌نام مشتری فعلی OTP و هدیه۴۸ساعت/۲مصاحبه را حفظ کن؛ فیلد انتخاب فروشنده/درصد/نقش به فرم عمومی ثبت‌نام اضافه نکن. اتصال فروش سروری و از موبایل تأییدشده است و referralCode فعلی مستقل می‌ماند. تنظیمات هدیه یا بانک/واریز خودکار جدید نساز.

۷. تست رابط را با دو فروشنده و سوپرادمین انجام بده: جداسازی token/scope، شماره تکراری، نمایش Registered پس از OTP، FirstSale فقط بعد تأیید اشتراک، نبود پورسانت بسته مصاحبه، فیلتر روز ثبت‌نام شامل تمدیدها، مجموع کل با pageSize کوچک، منع انتخاب Holding/Requested/Paid/Returned، retry یک requestId و دوبارکلیک، ردیف تازه تمدید، انتقال با حفظ پورسانت قبل و ابطال ورود پس از غیرفعال/reset. mock فقط تست باشد و داده ساختگی به محصول وارد نشود.
