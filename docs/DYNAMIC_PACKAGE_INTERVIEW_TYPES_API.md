# انواع مصاحبه و تعرفه‌های داینامیک پکیج — 2026-10-18

این قرارداد جایگزین ADR-069 و بخش قیمت نوع مصاحبه در اسناد قبلی است.

## مدل دیتابیس

- `InterviewTypes`: کد پایدار و یکتا، نام نمایشی، `engineType`، وضعیت فعال، ترتیب و `rowVersion`.
- `PackageInterviewTypes`: کلید مرکب `packageId + interviewTypeCode`، قیمت هر دقیقه به دلار با دقت شش رقم و وضعیت فعال مستقل در هر پکیج.
- دو ستون `AiPricePerMinuteUsd` و `SpecializedAiPricePerMinuteUsd` از `PricingPackages` حذف می‌شوند. قیمت واقعی فقط از رابطه جدید خوانده می‌شود.
- تعداد و کد انواع مصاحبه محدود به general/specialized نیست. هر نوع جدید یکی از دو راهبرد اجرایی موجود `general` یا `specialized` را انتخاب می‌کند. ساخت موتور AI جدید با ایجاد یک رکورد دیتابیس انجام نمی‌شود. کد و راهبرد نوع پس از ایجاد قابل تغییر نیستند؛ نام، وضعیت و ترتیب قابل ویرایش‌اند.
- نوع انتخاب‌شده در `InterviewSessions.PricingInterviewTypeCode` نگهداری می‌شود؛ قابلیت اجرایی قبلی نیز snapshot می‌شود تا گزارش و موتور عمومی/تخصصی درست کار کنند. قالب‌ها به کد داینامیک با FK متصل‌اند.

## تعرفه‌های اولیه مصوب کاربر

| پکیج اولیه | عمومی | تخصصی |
|---|---:|---:|
| پایه | 0.03 USD/min | ندارد |
| پیشرفته | 0.03 USD/min | 0.05 USD/min |

Migration `NormalizePackageInterviewTypes` نوع‌های اولیه را می‌سازد و قیمت‌های مصوب بالا را برای کاتالوگ موجود اعمال می‌کند. دسترسی اولیه از قابلیت‌های قبلی هر پکیج منتقل می‌شود؛ پکیج دارای `technical_interview` حتی اگر ستون تخصصی قبلی null باشد، تعرفه تخصصی 0.05 می‌گیرد. مقدار قدیمی تخصصی در پکیج فاقد قابلیت با وضعیت غیرفعال به رابطه منتقل می‌شود، با نرخ مصوب جدید. صورتحساب، خرید، کیف پول و رزروهای تاریخی بازنویسی نمی‌شوند.

## مدیریت سوپرادمین

همه مسیرها نیازمند احراز هویت مستقل سوپرادمین و قرارداد موجود `X-Admin-Entry` هستند. توکن کارفرما مجاز نیست.

| روش | مسیر | کاربرد |
|---|---|---|
| GET | `/api/admin/pricing/interview-types` | تمام انواع فعال و غیرفعال |
| POST | `/api/admin/pricing/interview-types` | ایجاد نوع |
| PUT | `/api/admin/pricing/interview-types/{code}` | تغییر نام، ترتیب و وضعیت نوع |
| GET | `/api/admin/pricing/packages/{id}` | جزئیات پکیج شامل تمام `interviewTypes` |
| PUT | `/api/admin/pricing/packages/{id}/interview-types/{code}` | افزودن رابطه، تغییر قیمت یا فعال/غیرفعال‌سازی |

ایجاد نوع:

```json
{"code":"leadership","name":"مصاحبه رهبری","engineType":"general","isActive":true,"sortOrder":3}
```

ویرایش نوع، شامل نسخه همان نوع:

```json
{"type":{"code":"leadership","name":"مصاحبه رهبری","engineType":"general","isActive":false,"sortOrder":3},"rowVersion":"BASE64_FROM_TYPE"}
```

تنظیم نوع در پکیج، شامل نسخه همان پکیج:

```json
{"pricePerMinuteUsd":0.03,"isActive":true,"rowVersion":"BASE64_FROM_PACKAGE"}
```

پاسخ تنظیم رابطه، پکیج کامل و `rowVersion` جدید آن است. تغییر همزمان با نسخه قدیمی 409 است؛ قیمت باید مثبت، حداکثر 1000 دلار و با حداکثر شش رقم اعشار باشد. رابطه تکراری ایجاد نمی‌شود؛ PUT همان رابطه را ویرایش می‌کند. حذف فیزیکی در API نداریم؛ غیرفعال‌سازی تاریخچه را حفظ می‌کند.

برای سازگاری، ورودی‌های قدیمی قیمت عمومی/تخصصی در API قدیمی پکیج هنوز به رابطه مربوط تبدیل می‌شوند؛ ستون جدا یا منبع قیمت دوم نیستند. کلاینت جدید باید فقط API رابطه و آرایه `interviewTypes` را مصرف کند. ساخت پکیج بدون ارسال قیمت قدیمی مجاز است؛ تا تعیین رابطه قیمت، دعوت آن نوع قابل ایجاد نیست. فیلدهای قدیمی snapshot قرارداد و trial فقط تاریخچه/سازگاری‌اند؛ صفر در قرارداد جدید بدون عمومی به معنی نداشتن نرخ عمومی است، نه مصاحبه رایگان.

## کاتالوگ و برآورد کارفرما

- `GET /api/pricing/interview-types`: فهرست داینامیک انواع فعال برای انتخابگر.
- `GET /api/pricing/packages`: هر پکیج آرایه `interviewTypes` دارد؛ فقط روابط فعال با نوع فعال برمی‌گردند. هر عضو شامل `code`, `name`, `engineType`, `pricePerMinuteUsd`, `pricePerMinuteRial`, `isActive`, `typeIsActive`, `currency: "IRR"` است.
- `GET /api/interview-pricing/quote?templateId=...&packageId=...&interviewType=leadership`: تعرفه همان ترکیب پکیج/نوع از DB و معادل ریالی با نرخ جاری خوانده می‌شود. بدون packageId، پکیج اشتراک فعال مبناست؛ انتخاب پکیج فقط پیش‌نمایش است و مجوز خرید یا رزرو واقعی نمی‌سازد.
- `pricePerMinuteRial = round(pricePerMinuteUsd × rialPerUsdt, 6, ToEven)`؛ رزرو کل بر اساس حداکثر مدت قالب است. نرخ پنج‌دقیقه‌ای و fallback آخرین نرخ معتبر طبق قرارداد قبلی حفظ می‌شود.
- پاسخ مدیریتی قیمت دلاری را همیشه دارد و معادل ریالی بدون دریافت FX، null است؛ قیمت ریالی زنده از کاتالوگ عمومی یا quote خوانده شود. عملیات مدیریت به سرویس نرخ وابسته نیست.
- قالب wizard، دعوت wizard و quote کد داینامیک می‌پذیرند. مسیر کلاسیک ایجاد دعوت نیز `interviewType` اختیاری دارد؛ در نبود آن، کد از `requiredCapabilityCode` قدیمی تعیین می‌شود.
- نبود قیمت/رابطه 409 `package_interview_price_not_configured`؛ رابطه غیرفعال 403 `package_interview_type_disabled`؛ نوع ناشناخته/غیرفعال 409 `interview_type_unavailable` است. هیچ fallback به نوع یا پکیج دیگر نداریم.

منبع اجازه نوع، رابطه فعال پکیج/نوع است؛ فلگ‌های قدیمی `hr_interview`/`technical_interview` دیگر منبع مجوز نوع‌های جدید نیستند. اشتراک فعال، قابلیت AI و قابلیت‌های مستقل سؤال تطبیقی همچنان بررسی می‌شوند. تنظیم رابطه تخصصی فعال برای یک پکیج، آن را برای دعوت‌های جدید تخصصی مجاز می‌کند؛ نباید فلگ قدیمی را جداگانه هم فعال کرد.

## تاریخچه و انتشار

تعرفه دلاری، نرخ ارز و مبلغ ریالی هنگام ساخت دعوت ذخیره و رزرو می‌شوند. تغییر قیمت/وضعیت فقط روی quote و دعوت جدید اثر دارد؛ شروع/تسویه دعوت موجود بدون نرخ تازه و با snapshot قبلی انجام می‌شود. جایگزینی دعوت، دعوت جدید است و دوباره قیمت/فعال‌بودن رابطه را بررسی می‌کند. اطلاعات مالی به کارجو ارسال نمی‌شود.

قبل از API جدید، migration افزایشی باید روی دیتابیس مقصد اعمال شود. Down تنها برای وضعیتی که بدون از دست رفتن داده در ساختار دو نوع قبلی قابل بازنمایی باشد مجاز است و قیمت‌ها را به ستون‌های قبلی برمی‌گرداند؛ وجود نوع سفارشی، تنظیمات ناسازگار یا قرارداد جدید بدون تعرفه عمومی با خطای PostgreSQL مانع rollback می‌شود. برای وضعیت‌های دیگر باید backup معتبر بازیابی شود. این تغییر فقط در کد و PostgreSQL آزمایشی محلی اعمال شده است. Angular در ریپوی جداست؛ صفحه سوپرادمین و انتخابگر کارفرما باید به قرارداد بالا متصل شوند.
