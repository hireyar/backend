# اعتبار ثابت ریالی و رزرو هنگام ایجاد دعوت

قرارداد جاری 2026-10-17؛ این سند و AI_RIAL_DISPLAY_API.md جایگزین مدل قبلی «اعتبار دلاری با معادل ریالی متغیر» هستند. Angular در این مخزن نیست؛ این تغییر، بک‌اند، migration و قرارداد اتصال فرانت را پوشش می‌دهد.

## رفتار مالی

- واحد واقعی کیف پول، ledger، اعتبار هدیه، محصول شارژ و snapshot اعتبار خرید **IRR** است. افزایش یا کاهش نرخ ارز موجودی را تغییر نمی‌دهد. CreditAmountRial مبلغ پایه اعتبار است و در نرخ دلار ضرب نمی‌شود.
- هزینه پایه مصرف هر دقیقه طبق قرارداد پکیج همچنان USD است. هنگام **ساخت دعوت‌نامه** سرور نرخ جاری را می‌گیرد، هزینه هر دقیقه ریالی و حداکثر هزینه مدت قالب را محاسبه و snapshot می‌کند. موجودی قابل‌استفاده زیر قفل سازمان بررسی می‌شود؛ در کمبود اعتبار409/insufficient_ai_credit و در نبود نرخ503/ai_display_rate_unavailable؛ دعوت ناقص ساخته نمی‌شود.
- دعوت، reservation و InterviewBilling در یک transaction ساخته می‌شوند؛ تماس نرخ و آپلود فایل خارج قفل‌اند. نرخ منقضی پذیرفته نمی‌شود. دو دعوت همزمان نمی‌توانند اعتبار مشترک را دوبار مصرف کنند.
- balance مجموع اعتبار باقی‌مانده است؛ reservedCredit جمع رزروهای فعال و availableCredit=balance−reservedCredit. رزرو، بدهکارکردن ledger نیست. پس از پایان، فقط مصرف واقعی از balance کم می‌شود و کل رزرو بسته می‌شود؛ بخش مصرف‌نشده خودکار به availableCredit برمی‌گردد. دوباره‌شارژکردن بخش آزادشده، خطای دوبار حساب‌کردن است.
- شروع مصاحبه نرخ تازه نمی‌گیرد و رزرو دوم نمی‌سازد؛ افزایش نرخ یا قطع سرویس نرخ، رزرو معتبر را تغییر نمی‌دهد. هزینه با ثانیه‌های billable معتبر سمت سرور و ratePerMinuteRial ثبت‌شده در دعوت محاسبه می‌شود؛ زمان بیکار مرورگر مصرف محسوب نمی‌شود.
- لغو دعوت رزرو را آزاد می‌کند؛ انقضای دعوت بدون شروع هزینه صفر دارد. رزرو مصاحبه شروع‌شده پس از حداکثر مدت نیز با ثانیه‌های واجد شرایط تسویه می‌شود. پاک‌سازی انقضا در مسیرهای خواندن/تغییر کیف پول و ساخت دعوت انجام می‌شود؛ worker تازه اضافه نشده است.
- ارسال مجدد، مصاحبه قبلی را با همان قرارداد قدیمی تسویه و دعوت جدید را با نرخ جدید رزرو می‌کند؛ هر دو زیر یک قفل و transaction هستند. کمبود اعتبار یا خطا کل جایگزینی را rollback می‌کند.
- شروع دعوت تاریخیِ بدون رزرو ریالی معتبر مجاز نیست؛ کارفرما باید دعوت را دوباره صادر کند. جلسات قدیمی دارای reservation در migration با نرخ cutover ثابت تبدیل می‌شوند.

## ثبت دلاری صرفاً در دیتابیس

طبق درخواست صریح کاربر، مقدار مصرف دلاری برای سوابق مالی محفوظ است ولی **هیچ‌جا نمایش داده نمی‌شود**:

| رکورد دیتابیس | فیلد | معنی |
| --- | --- | --- |
| InterviewBillings | RatePerMinuteUsd | قیمت پایه دلاری قرارداد |
| InterviewBillings | RialPerUsdt، RateQuotedAtUtc، RatePerMinuteRial | snapshot نرخ و هزینه ریالی هنگام دعوت |
| InterviewBillings | BilledAmountUsd | مصرف دلاری نهایی طبق ثانیه billable |
| InterviewBillings | BilledAmountRial | بدهی واقعی ریالی |
| AiCreditTransactions | Amount | اثر ریالی بر اعتبار |
| AiCreditTransactions | AmountUsd | اثر دلاری مصرف، منفی برای بدهکارشدن، null برای شارژ/اصلاح ریالی |

محاسبات با decimal و گردکردن نهایی شش رقم مطابق BillingMath هستند. USD audit و هزینه ریالی از نرخ‌های مربوط به خودشان و ثانیه یکسان محاسبه می‌شوند؛ به‌علت گردکردن مستقل، از ضرب مقدار USD گرد‌شده برای تعیین بدهی ریالی استفاده نشود. DTOهای مالی شامل AmountUsd یا BilledAmountUsd نیستند؛ مقدار USD وارد API سوابق، مصرف، فاکتور یا صفحه کارجو نمی‌شود. فیلد قیمت پایه دلاری پکیج در کاتالوگ/تنظیمات قیمت، «مصرف دلاری سوابق» نیست.

## APIهای ثابت و پویا

`GET /api/billing/ai-credit` و wallet در `GET /api/billing/panel` اعتبار واقعی IRR را بدون مراجعه به نرخ برمی‌گردانند؛ displayRate=null است. تراکنش‌ها، مصرف، تاریخچه، اعتبار خرید و فاکتور نیز مقادیر ذخیره‌شده ریالی ثابت دارند. payment و درگاه نقدی قبلی IRT باقی می‌مانند، ولی پاسخ HTTP پول پرداختی مثل قبل با ضریب ثابت۱۰ به IRR تبدیل می‌شود. نرخ پایه اشتراک در پاسخ‌های عمومی مالی دیگر با نرخ لحظه‌ای بازحساب نمی‌شود؛ aiRatePerMinuteRial و estimatedAvailableMinutes ممکن است null باشند؛ برای برآورد از quote دعوت استفاده شود.

`GET /api/pricing/packages` قیمت AI لندینگ را همچنان با نرخ جاری تبدیل می‌کند. cache نرخ موجود پنج ثانیه است. `GET /api/pricing/ai-credit-packages` مبلغ ثابت CreditAmountRial و مبلغ ثابت خرید را برمی‌گرداند. `CreditPackageRequest.creditAmountRial` و `AdjustmentRequest.amount` اکنون ریال واقعی هستند؛ گزینه تنظیم هدیه `RegistrationTrial:CreditAmountRial` است (پیش‌فرض کلاس۱٬۰۰۰٬۰۰۰ریال، تنظیم فعلی appsettings۵۰۰٬۰۰۰ریال). کلید قدیمی CreditAmountUsd معتبر نیست.

### پیش‌نمایش مخصوص کارفرما

`GET /api/interview-pricing/quote?templateId={id}`

JWT پنل و نقش Owner یا Recruiter لازم است؛ قالب فقط از سازمان جاری خوانده می‌شود. توکن دعوت کارجو به این API دسترسی ندارد. این API فقط پیش‌نمایش است و چیزی رزرو نمی‌کند:

```json
{
  "templateId": "11111111-1111-1111-1111-111111111111",
  "currency": "IRR",
  "ratePerMinuteRial": 50000,
  "maximumReservedRial": 250000,
  "hasSufficientCredit": true,
  "rate": {
    "currency": "IRR",
    "rialPerUsdt": 1000000,
    "fetchedAtUtc": "2026-10-17T10:00:00Z",
    "expiresAtUtc": "2026-10-17T10:01:00Z",
    "refreshAfterSeconds": 60
  }
}
```

قالب نمونه پنج دقیقه و قیمت پایه۰٫۰۵دلار است. خروجی عمومی نرخ و metadata هیچ نام تأمین‌کننده یا فیلد source/symbol ندارند. ثبت دعوت مستقل از مقدار نمایشی، نرخ تازه معتبر سمت سرور را می‌گیرد؛ مقادیر مبلغ/نرخ ارسال‌شده از کلاینت مرجع حسابداری نیستند.

## پرامپت آماده فرانت

مدل اعتبار HireYar را مطابق قرارداد RIAL_AI_WALLET_API.md پیاده کن. **تمام اطلاعات نرخ، هزینه، موجودی، رزرو و شمارش معکوس فقط متعلق به پنل کارفرماست. کارجو نباید در صفحه دعوت/ورود/مصاحبه هیچ مبلغ یا نرخ یا کنترل مالی ببیند.**

اعتبار بالای داشبورد را مستقیم از availableCredit ریالی API کیف پول/پنل بگیر؛ balance و reservedCredit را در جزئیات با برچسب روشن نشان بده. نرخ دلار را در موجودی ضرب نکن و با رفرش قیمت ارز موجودی را تغییر نده. کیف پول را پس از شارژ، ایجاد/لغو/ارسال مجدد دعوت و تسویه و هنگام بازگشت به پنل بازخوانی کن؛ polling نرخ برای موجودی لازم نیست. مبلغ محصول شارژ CreditAmountRial ثابت است؛ اعتبار هدیه و اصلاح ادمین هم ریالی هستند. فرم شارژ/اصلاح را به دلار تبدیل نکن.

در **پنل کارفرما، صفحه ساخت دعوت کارجو** بعد از انتخاب قالب، GET /api/interview-pricing/quote?templateId=... را بگیر. نرخ rate.rialPerUsdt را با عنوان «نرخ فعلی دلار» و واحد ریال نشان بده؛ ratePerMinuteRial هزینه هر دقیقه و maximumReservedRial حداکثر رزرو است. قیمت فقط پیش‌نمایش است؛ هنگام ثبت، تصمیم و نرخ معتبر با سرور است. نام تأمین‌کننده، source، لینک یا لوگوی آن را هیچ‌جا نشان نده.

زیر نرخ فعلی، یک **دایره کوچک ۱۲ تا ۱۶ پیکسلی** با حلقه پیشرفت زمانی قرار بده؛ کنار آن متن کوتاه «به‌روزرسانی در ۴۳ ثانیه» باشد. این حلقه مقدار باقی‌مانده تا expiresAtUtc را نشان بدهد، نه یک spinner بزرگ و بی‌نهایت. progress=remainingMs/60000، countdown=ceil(remainingMs/1000)؛ با ساعت یکنواخت مرورگر و deadline واقعی کار کن تا sleep/tab باعث drift نشود. برای خوانایی متن و aria-label داشته باش؛ هر ثانیه aria-live را تکرار نکن. اگر prefers-reduced-motion فعال بود، حرکت نرم حلقه حذف شود ولی عدد باقی بماند. هنگام پایان، یک درخواست تازه بفرست و حلقه را با deadline پاسخ تازه آغاز کن. هنگام دریافت واقعاً معلق، همان دایره کوچک می‌تواند indeterminate شود. در hidden تب polling متوقف و در بازگشت نرخ تازه گرفته شود؛ intervalها در destroy پاک و درخواست‌های قدیمیِ قالب عوض‌شده لغو شوند. درخواست‌ها overlap نشوند.

فقط این قیمت دعوت هر یک دقیقه تازه شود. قیمت هزینه AI در لندینگ همچنان از پاسخ پویای pricing/packages بیاید و با نرخ جدید بازخوانی شود؛ موجودی ثابت کاربر به این جریان متصل نباشد. همه اعداد مالی پاسخ ریالی هستند؛ فرانت فقط در صورت درخواست نمایش تومان می‌تواند در formatter بر۱۰ تقسیم کند. مقدار null هزینه/دقیقه در داشبورد را با صفر یا عدد ساختگی جایگزین نکن.

خطای503 نرخ یا countdown منقضی را با «دریافت نرخ فعلی ممکن نیست» و retry در همان پنل کارفرما نشان بده؛ مبلغ منقضی را نرخ جاری معرفی نکن. خطای409 insufficient_ai_credit هنگام ثبت باید پیام کمبود اعتبار و بازخوانی کیف پول بدهد و دعوت موفق ساختگی نشان ندهد. ثبت مصرف دلاری صرفاً دیتابیس است؛ در جدول سوابق مالی، جزئیات، چاپ، tooltip و صفحه کارجو هیچ مصرف دلاری نمایش نده.

## مهاجرت موجودی‌های قبلی

Migration: `20261017195309_PersistRialAiCredit`. انتشار باید API و فرانت هماهنگ و پس از migration باشد. برای دیتابیس قدیمی دارای اعتبار، یک نرخ cutover صحیح ریال بر دلار در session پایگاه داده تنظیم شود:

```sql
SET hireyar.ai_credit_cutover_rial_per_usd = '650000'; -- فقط نمونه؛ نرخ واقعی بررسی‌شده را جایگزین کنید
```

SQL migration باید در **همان اتصال/session** اجرا شود؛ SET در ترمینال جدا روی dotnet ef اثر ندارد. اسکریپت idempotent را با همان psql session پس از SET اجرا کنید. این نرخ یک‌بار در AiCreditCurrencyCutover ثبت می‌شود. بدون نرخ معتبر migration روی داده قبلی متوقف و transaction rollback می‌شود؛ USD صرفاً تغییر برچسب داده نمی‌شود. ضریب صحیح، زنجیره ledger شش‌رقمی را بدون خطای گردکردن تبدیل می‌کند. در دیتابیس کاملاً بدون داده مالی نیاز به نرخ نیست. DDL، ledger، wallet، رزرو و snapshotها اتمیک تبدیل می‌شوند؛ مقدار مصرف USD تاریخی در ستون خصوصی می‌ماند. Down به‌علت تغییر واحد پول مجاز نیست؛ بازگشت با backup قبل cutover است. این migration در مقصد اعمال نشده است.
