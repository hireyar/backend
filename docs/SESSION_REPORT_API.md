# گزارش مصاحبه جدید — قرارداد مرحله اول

وضعیت 2026-10-15: موتور قبلی گزارش با درخواست صریح کاربر حذف و این مسیر از ابتدا نوشته شد. این سند مرجع جاری است؛ قراردادهای evaluation-report، report-v3 و lifecycle قدیمی بازنشسته‌اند. این مرحله گزارش پایه و طراحی بخش‌هاست، نه تکمیل ارزیابی AI. Angular در این ریپو نیست.

## قرارداد API

- `GET /api/interviews/{id}/report`: خواندن فوری اطلاعات ثبت‌شده جلسه؛ بدون تولید، صف، worker، تماس AI یا ذخیره گزارش مشتق‌شده. نقش Owner یا Recruiter همان سازمان، جلسه حذف‌شده/سازمان دیگر 404؛ بدون احراز هویت 401. پاسخ NoStore است.
- `GET /api/interviews/{id}/report/print`: چاپ HTML مستقل با RTL و CSS چاپ، escape متن ورودی و CSP؛ ذخیره PDF توسط مرورگر. خروجی PDF سمت سرور و داشبورد Angular هنوز ساخته نشده‌اند.
- مسیرهای GET قدیمی evaluation-report/status/print و POST evaluation-report/regenerate پس از کنترل سازمان، 410 با `report_api_retired` می‌دهند. POST قدیمی همچنان Owner می‌خواهد. هیچ adapter یا تولیدکننده قدیمی اجرا نمی‌شود.
- اگر قرارداد billing جلسه ثبت شده، قابلیت snapshotشده `interview_report` لازم است؛ نبود آن 403 است. جلسه پیش از billing/شروع، فقط اطلاعات پایه موجود را دارد. سرویس از قرارداد مالی موجود استفاده می‌کند و رزرو/تسویه را تغییر نمی‌دهد.

`schemaVersion=session-report/1`؛ `state=BaseReady` برای جلسه Completed و `InterviewIncomplete` برای بقیه وضعیت‌ها. BaseReady فقط آماده بودن اطلاعات پایه است و به معنی کامل بودن تحلیل نیست. تکمیل جلسه بلافاصله قابل خواندن است؛ GET منتظر مدل نمی‌ماند. شکست احراز هویت/دیتابیس همچنان خطای واقعی است؛ تضمین دسترسی در قطعی زیرساخت یا ساختن نمره بدون ارزیابی مطرح نیست.

ریشه JSON: `identity`, `statistics`, `access`, `questions`, `media`, `signals`, `overallScore`, `summary`, `strengths`, `improvements`, `sections` و interviewId/schemaVersion/state.

## بخش‌های طراحی و ترتیب ساخت

| code | بخش | وضعیت این مرحله |
|---|---|---|
| navigation | دسترسی‌ها، چاپ و رسانه | URL چاپ و رسانه خصوصی؛ کنترل‌های صفحه در Angular |
| identity | شناسنامه کارجو و مصاحبه | نام، عنوان snapshot موقعیت، نوع، وضعیت و زمان‌های UTC |
| score | امتیاز کل و اطمینان | NotStarted؛ مقدار و فرمول null |
| positionFit | تناسب با موقعیت | NotStarted |
| statistics | آمار مصاحبه | محاسبه از داده واقعی |
| summary | جمع‌بندی | NotStarted؛ متن null |
| strengthsAndImprovements | نقاط قوت و زمینه‌های بهبود | NotStarted؛ فهرست‌های خالی |
| specializedProfile | پروفایل تخصصی | NotStarted در تخصصی، NotApplicable در عمومی |
| generalProfile | شاخص‌های عمومی | NotStarted در عمومی، NotApplicable در تخصصی |
| questions | سؤال، پاسخ، تعامل و ارزیابی | داده واقعی آماده؛ assessment هنوز NotStarted |
| signals | رسانه، رضایت و رویدادها | داده ثبت‌شده، همراه وضعیت نامشخص/مفقود/منقضی |
| humanReview | بررسی و تصمیم کارشناس در گزارش | طراحی جدید هنوز NotStarted |

فرانت باید همه بخش‌های applicable را از اولین پاسخ نمایش دهد؛ برای NotStarted پیام صریح «هنوز ارزیابی نشده» نمایش دهد و از نمایش صفر به جای null یا spinner سراسری خودداری کند. schema قبلی را به این DTO نگاشت نکند. نمونه HTML کاربر مرجع بصری و ترتیب بخش‌هاست؛ عددها، نمره‌ها و متن‌های نمایشی آن، داده واقعی یا دستور تولید نیستند. چاپ فعلی پوسته اولیه مستقل است؛ تعامل‌های داشبورد در ریپوی Angular ساخته می‌شوند.

## داده‌های پایه و رفتار نقص داده

`questions` فقط سؤال واقعاً پرسیده‌شده یا دارای پاسخ را دارد؛ بانک استفاده‌نشده وارد گزارش نمی‌شود. ترتیب زمان پرسش و ترتیب جلسه، شماره نمایشی را مشخص می‌کند. `answer` پاسخ نهایی و `clarifications` تعامل‌ها هستند. سؤال بی‌پاسخ `Unanswered`، پاسخ Failed یا در حال پردازش با همان وضعیت و transcript nullable دیده می‌شود؛ گزارش از ارزیابی لحظه‌ای قدیمی نمره استخراج نمی‌کند. متن ذخیره‌شده AssistantMessage فقط سابقه تعامل است.

آمار: AskedQuestions، BankQuestions، SubmittedAnswers، ProcessedAnswers، UnansweredQuestions، FailedAnswers، ClarificationTurns، متوسط مدت پاسخ‌های دارای duration و سطوح سؤال‌های پرسیده‌شده. مدت نامعلوم null است؛ شماره سطح یا تعداد سؤال معادل کیفیت کارجو نیست.

رسانه فقط URL داخلیِ نیازمند احراز هویت دارد؛ storageKey یا لینک عمومی صادر نمی‌شود. نبود ضبط `Missing`، ضبط آپلودشده `UploadedUnverified` و پایان retention برابر `Expired` است. وجود metadata، سلامت فایل یا کامل بودن ضبط را اثبات نمی‌کند. timeline نامعتبر فقط TimelineState=Unavailable و فهرست خالی می‌دهد؛ لینک مجاز ویدیو مستقل می‌ماند. timeline معتبر `CandidateReported` است، نه زمان‌بندی تأییدشده سرور. انقضای رسانه، اطلاعات متنی گزارش را حذف نمی‌کند.

رویدادهای خام کارجو با ActorUserId=null خوانده می‌شوند؛ رضایت Accepted/Revoked از آخرین رویداد مربوط و در نبود داده Unknown است. DeviceState فقط در صورت گزارش قطع میکروفون/دوربین ReportedIssue و در غیر این صورت Unknown است؛ سکوت telemetry دلیل سلامت یا نبود تقلب نیست.

## مرحله‌های بعدی — طراحی، هنوز پیاده نشده

1. ارزیابی مستقل هر پاسخ با شناسه واقعی سؤال/پاسخ و شواهد متعلق به همان پاسخ؛ ثبت نتیجه، نسخه ارزیاب و علت محدود شکست همان بخش. شکست یک پاسخ، سایر داده‌های گزارش را پنهان نکند.
2. پروفایل تخصصی/عمومی و تناسب، متکی به ارزیابی‌های معتبر؛ وزن‌ها و مخرج پوشش مشخص. محاسبه امتیاز و آمار توسط سرور، با null برای شواهد ناکافی. نمودار از همان محاسبات ساخته شود.
3. جمع‌بندی، نقاط قوت/بهبود و بررسی انسانی در بخش‌های جدا؛ وضعیت هر بخش مستقل و قابل بازیابی، تلاش محدود و قابل مشاهده. خطاهای قابل پیش‌بینی کد ثابت داشته باشند؛ خروجی خام/اطلاعات کارجو وارد لاگ نشود.
4. اتصال کامل Angular و چاپ/PDF نهایی؛ داده پایه هنگام شکست بخش تحلیلی همچنان نمایش داده شود. برای تحلیل‌های ناتمام پیام دقیق بدهد؛ کامل بودن صفحه را با موفقیت تمام تحلیل‌ها یکی نگیرد.

در این مرحله stateهای job، retry، repair، evaluator، جدول تحلیل، فرمول نمره و مدل AI جدید عمداً پیاده نشده‌اند. طراحی جزئی قرارداد آن‌ها در مرحله مربوط انجام می‌شود؛ backlog مجوز اجرای خودکار مرحله بعد نیست.

## حذف قدیمی و migration

سرویس، DTO، validator، prompt، source resolver، metric catalog، lifecycle، worker، provider report method، چاپ و entity/configuration قدیمی حذف شدند؛ تنظیمات EvaluationModel/EvaluationTimeoutSeconds نیز حذف شده‌اند. مسیر live/STT/TTS/بانک سؤال تغییر کاربرد ندارد. ثبت رویداد کارجو، ضبط رسانه و API موجود تصمیم انسانی امکانات مشترک مصاحبه‌اند و حفظ شده‌اند؛ قرارداد جدید به سرویس/DTO تولید گزارش قبلی وابسته نیست.

Migration `20261015080151_RemoveLegacyEvaluationReports` فقط جدول `InterviewEvaluationReports` و محتویات آن را حذف می‌کند؛ هیچ جدول مصاحبه، رسانه، رویداد، تصمیم یا مالی حذف نمی‌شود. Down تنها جدول خالی را بازمی‌سازد و نتایج حذف‌شده را برنمی‌گرداند. migrationهای تاریخی برای زنجیره EF نگه داشته شده‌اند و کد runtime قابل استفاده مجدد نیستند.

برای انتشار: همه نسخه‌های قدیمی API/worker را متوقف کنید، migration را اعمال و سپس نسخه جدید API را اجرا کنید؛ اجرای همزمان نسخه قبلی پس از DROP مجاز نیست چون هنگام completion هنوز جدول صف قدیمی را می‌نویسد. Angular باید به مسیر و schema جدید منتقل شود. در این تغییر migration روی مقصد اعمال و push/deploy انجام نشده است.
