# تنظیمات حساب و نام سازمان

قرارداد جاری 2026-10-13؛ پنل Angular در ریپوی جداست. این تغییر فقط API است.

## خواندن

`GET /api/auth/me` با Bearer token پاسخ جاری `CurrentUserDto` شامل `fullName`، `organizationName` و `organizationId` را می‌دهد. فرم از همین پاسخ مقدار اولیه می‌گیرد.

## ذخیره

`PUT /api/auth/me` با Bearer token و JSON:

```json
{
  "fullName": "نام کاربر",
  "organizationName": "شرکت نمونه"
}
```

نام شخص اجباری است. نام سازمان در قرارداد برای سازگاری با کلاینت قبلی اختیاری است؛ حذف فیلد یا null نام سازمان فعلی را حفظ می‌کند. اگر مقدار ارسال شود، باید ۱ تا ۲۰۰ کاراکتر و غیرخالی/غیرصرفاً whitespace باشد. فاصله ابتدا و انتها پیش از ذخیره حذف می‌شود. ورودی بیش از۲۰۰ حتی با فاصله اضافه رد می‌شود. اعتبارسنجی نام شخص طبق قرارداد قبلی Required/StringLength(200) است.

فقط Owner می‌تواند نام سازمان را تغییر دهد؛ شناسه سازمان از حساب بررسی‌شده سرور خوانده می‌شود. `organizationId`، `role` یا سایر فیلدهای خارج DTO در درخواست پذیرفته نمی‌شوند. نام شخص و سازمان در یک تراکنش ذخیره می‌شوند؛ نام سازمان روی `Organization.Name` موجود، بدون ستون تازه یا تغییر شناسه است.

موفقیت200 همان DTO جاری را با نام‌های ذخیره‌شده برمی‌گرداند. `GET /api/organization` نیز نام تازه را برمی‌گرداند و `PUT /api/organization` قبلی محفوظ است. هیچ مصرف جدیدی در snapshot جلسه‌های تاریخی اضافه نشده است.

خطاها: ورودی نامعتبر400 (برای صرفاً whitespace کد `invalid_organization_name`؛ سایر محدودیت‌ها ProblemDetails اعتبارسنجی مدل)، بی‌هویت401، نقش نامجاز403، نبود سازمان404. فرانت خطا را نمایش دهد و در شکست پیام موفقیت یا مقدار ذخیره‌شده جعلی نمایش ندهد.

## اتصال فرانت

در «تنظیمات حساب شما» کنار نام شخص، ورودی «نام سازمان» با maxlength=200 قرار گیرد؛ فرم با پاسخ me مقداردهی و هر دو فیلد با یک PUT ذخیره شوند. پس از موفقیت، state کاربر/سازمان از پاسخ سرور به‌روز شود تا بخش‌های مصرف‌کننده همان نام را استفاده کنند. ذخیره درحال‌اجرا دکمه را غیرفعال کند. توکن و شناسه سازمان در فرم ورودی نیستند. رابط درخواست TypeScript می‌تواند organizationName اختیاری باشد ولی این فرم هر دو نام را ارسال می‌کند.
